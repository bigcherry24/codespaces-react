SESSION 01 · 45–60 MIN

앱의 시작과 렌더링

브라우저에서 첫 화면까지의 경로를 따라갑니다. index.html의 `#root`를 찾고, index.jsx에서 React root 생성과 `App` 렌더링을 확인합니다.

학습 목표

  • HTML 진입점, React root, 앱 컴포넌트의 역할을 구분합니다.
  • `createRoot`와 `root.render`가 연결되는 이유를 설명합니다.

실습과 확인

`App.jsx`의 제목을 바꾸고 저장해 브라우저 갱신을 관찰합니다. “HTML → index.jsx → App → 화면” 흐름을 그려보세요.

SESSION 02 · 45–60 MIN

컴포넌트, JSX와 props

App.jsx가 화면을 구성하고, ScheduleDialog.jsx가 일정 입력을 담당합니다. 부모가 `schedule`, `onClose`, `onSave`를 전달하는 부분을 찾아보세요.

학습 목표

  • 컴포넌트를 화면의 책임 단위로 이해합니다.
  • JSX 표현식과 props 전달, callback을 통한 부모와 자식 간 상호작용을 추적합니다.

실습과 확인

모달 제목을 prop으로 전달하도록 바꾸어 봅니다. 데이터는 부모에서 자식으로 내려가고, 사용자의 저장 요청은 callback으로 부모에 전달되는 흐름을 설명합니다.

SESSION 03 · 45–60 MIN

useState와 이벤트

`App.jsx`에서 `visibleMonth`, `selectedDate`, `isDialogOpen`을 찾아 각 상태가 어떤 화면을 제어하는지 확인합니다.

학습 목표

  • state가 렌더링 사이에 보존되는 값임을 이해합니다.
  • 이벤트 → setter → 재렌더링 흐름을 설명합니다.

실습과 확인

“오늘” 버튼 handler에서 바뀌는 state를 먼저 예측하고 실제로 눌러 확인합니다. DOM 직접 변경 없이 새 상태로 UI가 다시 계산되는 이유를 말해보세요.

SESSION 04 · 45–60 MIN

배열 렌더링과 파생 데이터

달력의 42일 생성, `map`을 이용한 셀 렌더링, 날짜별 `filter`, 일정 `sort`를 App.jsx에서 살펴봅니다.

학습 목표

  • 배열에서 JSX 목록을 만들고 안정적인 `key`를 지정합니다.
  • 원본 state와 렌더링을 위한 파생 데이터를 구분합니다.

실습과 확인

날짜당 일정 표시 개수를 조절하고 초과 표시를 확인합니다. 선택 날짜 일정 목록을 별도 state로 저장하지 않고 계산할 수 있는 이유를 설명합니다.

SESSION 05 · 45–60 MIN

폼과 제어 컴포넌트

ScheduleDialog.jsx에서 입력 요소의 `value`와 `onChange`, 공통 handler, 제출 전 검증을 따라갑니다.

학습 목표

실습과 확인

SESSION 06 · 45–60 MIN

상태 업데이트와 CRUD

useSchedules.js에서 일정 추가·수정·삭제를 봅니다. `map`, `filter`, spread를 사용해 기존 배열을 직접 변경하지 않습니다.

학습 목표

  • 불변 업데이트가 React 상태 변경에 적합한 이유를 설명합니다.
  • 함수형 업데이트로 최신 배열을 기준 삼는 방법을 익힙니다.
  • 화면 이벤트와 데이터 관리 책임을 구분합니다.

실습과 확인

일정을 수정하고 제목만 바뀌는지 확인합니다. 나머지 필드가 보존되는 부분과 삭제 취소 시 일정이 그대로인 이유를 추적합니다.

SESSION 07 · 45–60 MIN

useEffect와 localStorage

같은 훅에서 초기 저장값을 읽는 부분과 `useEffect`로 변경 내용을 쓰는 부분을 비교합니다. 일정은 `JSON.stringify`/`JSON.parse`를 통해 브라우저 저장소에 기록됩니다.

학습 목표

  • 렌더링과 브라우저 저장소 동기화가 다른 일임을 이해합니다.
  • effect 의존성 배열이 다시 실행될 시점을 결정함을 확인합니다.
  • localStorage 데이터는 동일 브라우저에만 저장됨을 이해합니다.

실습과 확인

개발자 도구에서 `daybook-schedules-v1` 키를 확인하고 삭제해 봅니다. 저장 키를 바꾸면 기존 값이 어떻게 되는지 예측합니다.

SESSION 08 · 45–60 MIN

디버깅, 테스트와 기능 확장

기존 테스트는 기본 안내 화면을 대상으로 하므로 현재 일정 관리 UI에 맞게 변경하는 것이 학습 과제입니다. 테스트 환경은 vite.config.js에서 확인합니다.

학습 목표

  • 오류를 재현하고 상태 흐름을 거슬러 원인을 좁힙니다.
  • 사용자 관점의 테스트를 작성하고 빌드로 검증합니다.
  • 배운 개념을 활용해 작은 기능을 끝까지 구현합니다.

실습과 확인

빈 상태 개선, 일정 개수 표시, 제목 검색 중 하나를 골라 구현합니다. 요구사항을 작게 나누고, 어떤 state·props·저장 로직이 필요한지 먼저 설명한 뒤 검증합니다.

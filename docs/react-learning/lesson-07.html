useEffect와 localStorage

React 렌더링 밖의 브라우저 저장소와 동기화하고, 새로고침 후에도 데이터가 유지되는 원리를 익힙니다.

핵심: useEffect · dependency · persistence브라우저 API

이번 회차의 목표

  • 초기 state를 지연 초기화해 저장 데이터를 읽습니다.
  • `useEffect`가 렌더 후 동기화 작업을 수행하는 이유를 이해합니다.
  • `localStorage`는 같은 브라우저에만 저장되는 것을 확인합니다.

코드 따라가기

useSchedules.js는 state 초기값을 읽는 함수로 전달하고, state가 바뀔 때 effect에서 JSON으로 저장합니다.

const [schedules, setSchedules] = useState(readSchedules);

useEffect(() => {
  window.localStorage.setItem(
    STORAGE_KEY,
    JSON.stringify(schedules)
  );
}, [schedules]);

의존성 배열의 `schedules`가 바뀌면 effect가 다시 실행됩니다. 저장소는 문자열만 다루므로 객체 배열은 `JSON.stringify`와 `JSON.parse`를 거칩니다.

진행 순서

  1. 5분: 새로고침 전후 일정이 유지되는지 확인합니다.
  2. 10분: `localStorage`의 문자열 저장 방식 확인
  3. 15분: 초기 읽기와 effect 저장의 실행 순서 추적
  4. 15분: 개발자 도구에서 `daybook-schedules-v1` 확인 후 값 변경
  5. 5분: state와 영속 저장의 차이를 정리합니다.

실습

개발자 도구에서 `localStorage`의 `daybook-schedules-v1` 값을 삭제하고 새로고침해 보세요. 저장 키를 바꾸면 기존 일정이 어떻게 되는지도 예측하고 실험하세요.

  • 다른 컴퓨터에서도 이 데이터가 보이나요? 왜 그런가요?

상태 업데이트와 CRUD

일정 추가·수정·삭제를 추적하면서 React에서 배열과 객체 state를 불변 방식으로 갱신하는 이유를 배웁니다.

핵심: spread · map · filter · callback데이터 변경

이번 회차의 목표

  • 배열 state를 직접 변경하지 않고 새 배열로 갱신합니다.
  • 함수형 state 업데이트에서 최신 값을 사용하는 이유를 이해합니다.
  • CRUD 동작을 컴포넌트와 훅의 책임으로 나눠 설명합니다.

코드 따라가기

useSchedules.js는 일정 저장과 변경을 모아둔 커스텀 훅입니다. 추가는 새 배열, 수정은 `map`, 삭제는 `filter`로 기존 배열을 변경하지 않고 새 값을 만듭니다.

setSchedules((currentSchedules) =>
  currentSchedules.map((schedule) =>
    schedule.id === id
      ? { ...schedule, ...updates }
      : schedule
  )
);

함수형 업데이트는 이전 state를 인자로 받아 다음 state를 계산합니다. App은 사용자 동작을 받고 훅의 함수를 호출하며, 훅은 데이터 변경을 담당합니다.

진행 순서

  1. 5분: 일정 저장 전후 화면을 관찰합니다.
  2. 10분: 일정 객체의 id가 수정·삭제에 쓰이는 방식 확인
  3. 15분: add, update, delete 함수를 한 줄씩 추적
  4. 15분: 새 일정 등록, 수정, 삭제를 수행하고 목록 확인
  5. 5분: 각 책임이 어느 파일에 있는지 설명합니다.

실습

일정 수정 시 제목만 바꾸고 날짜·메모·색상은 유지되는 이유를 spread 연산자와 함께 설명하세요. 이어서 삭제 확인을 취소했을 때 데이터가 그대로인지 확인하세요.

마무리 질문

  • state 배열에 `push`를 직접 쓰지 않는 이유는 무엇인가요?
  • 수정할 대상을 어떻게 찾고 다른 항목은 어떻게 유지하나요?
  • 함수형 업데이트는 어떤 문제를 예방하나요?

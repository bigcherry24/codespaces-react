SESSION 03 · 45–60 MIN

useState와 이벤트

버튼을 누른 결과를 상태로 표현하고, 상태 변경이 React 화면을 다시 계산하게 하는 원리를 배웁니다.

핵심: state · setter · event handler화면 동작의 출발점

이번 회차의 목표

  • 렌더링 사이에 유지되는 state의 의미를 설명합니다.
  • setter 호출이 화면 갱신을 요청하는 것을 확인합니다.
  • 이벤트 핸들러와 렌더링 중 실행되는 코드를 구분합니다.

코드 따라가기

App.jsx에는 표시 월, 선택 날짜, 편집할 일정, 모달 열림 여부가 각각 state로 있습니다.

const [visibleMonth, setVisibleMonth] = useState(...);
const [selectedDate, setSelectedDate] = useState(...);
const [isDialogOpen, setIsDialogOpen] = useState(false);

예를 들어 다음 달 버튼은 `moveMonth(1)`을 호출합니다. 이 함수가 월 상태와 선택 날짜를 바꾸면 React가 최신 값을 바탕으로 UI를 다시 렌더링합니다. DOM을 직접 수정하지 않습니다.

진행 순서

  1. 5분: 달력에서 상호작용 가능한 버튼을 찾습니다.
  2. 10분: `useState`의 현재 값과 setter를 구분합니다.
  3. 15분: 이전 달·다음 달의 클릭부터 상태 변경까지 추적합니다.
  4. 15분: 모달 열림 state를 바꾸고 화면 변화를 관찰합니다.
  5. 5분: 이벤트 → setter → 재렌더링을 설명합니다.

실습

“오늘” 버튼의 handler에서 `visibleMonth`와 `selectedDate`가 각각 어떻게 바뀌는지 예측한 뒤 눌러 확인하세요. setter를 제거하면 어떤 부분이 달라지는지도 살펴보세요.

마무리 질문

  • 일반 변수 대신 state가 필요한 이유는 무엇인가요?
  • setter를 호출하면 React는 무엇을 다시 계산하나요?
  • 이벤트 handler는 언제 실행되나요?

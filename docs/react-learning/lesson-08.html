SESSION 08 · 45–60 MIN

디버깅, 테스트와 기능 확장

기능의 상태 흐름을 스스로 추적하고, 현재 화면에 맞는 테스트를 만든 뒤 작은 개선 하나를 완성합니다.

핵심: 관찰 · 재현 · 검증학습 과정 마무리

이번 회차의 목표

  • 버그를 작은 재현 절차로 좁힙니다.
  • 사용자 관점에서 화면 동작을 테스트합니다.
  • 학습한 state·props·effect를 활용해 작은 기능을 추가합니다.

코드 따라가기

기존 테스트는 기본 React 안내 화면의 문구를 기대하므로, 일정 관리 화면과 기대값이 다릅니다. 테스트 실패를 무시하는 대신 이 회차에서 새 화면의 핵심 사용자 동작에 맞게 테스트를 고치는 연습을 합니다.

setupTests.js는 DOM matcher를 추가하고, 테스트 환경은 vite.config.js의 Vitest 설정에서 `jsdom`으로 지정합니다.

npm test -- --run
npm run build

첫 명령은 테스트를 한 번 실행하고, 두 번째는 배포 빌드가 가능한지 확인합니다. 실패하면 오류 메시지와 실행 순서를 이용해 원인을 좁힙니다.

진행 순서

  1. 5분: 재현할 사용자 동작을 하나 선택합니다.
  2. 10분: 테스트의 준비·동작·기대 결과를 분리합니다.
  3. 15분: 달력 화면의 테스트를 하나 수정하거나 작성합니다.
  4. 15분: 작은 기능을 추가해 수동·자동으로 검증합니다.
  5. 5분: 변경 이유와 남은 한계를 동료에게 설명합니다.

확장 과제

예: 일정이 없는 날짜의 빈 상태 개선, 선택 날짜에 일정 개수 표시, 일정 제목 검색 중 하나를 선택합니다. 기능 하나만 구현하고, 어떤 state가 필요한지 먼저 설명한 뒤 코드를 수정하세요.

마무리 점검

  • 사용자 동작에서 화면 갱신까지 상태 흐름을 설명할 수 있습니다.
  • 테스트가 실제 사용자의 동작과 결과를 검증합니다.
  • 추가 기능의 데이터·상태·화면 책임을 구분했습니다.
  • localStorage의 한계와 서버 저장이 필요한 경우를 설명할 수 있습니다.

오늘의 흐름

  1. 동작 재현
  2. 원인 위치 좁히기
  3. 작게 수정
  4. 테스트·빌드 확인
